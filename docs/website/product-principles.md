# Product and implementation principles

## Visitor experience

Use a simple homepage to direct visitors to the main parts of the site. The role of interactive features remains open.

## Content structure

Use the current content as a guide to the site’s main areas: bio, CV, research background, and personal projects or posts.

Pages should feel like parts of the same site. Keep navigation, typography, and visual style consistent. A project-specific page hosted outside the site’s domain may have its own presentation.

## Implementation preferences

Nathan wants direct control over site content through an obvious, easy-to-edit source. Use Markdown for prose and a single clearly named YAML file for structured page content such as cards and lists. Keep page-specific wording, dates, links, and meaningful image text out of presentation templates where practical. Document the editing path when adding a section. This preference concerns content ownership and maintainability; other implementation trade-offs remain open.

## Change boundaries

No additional change boundaries were established in the interview. Follow the current instructions in `AGENTS.md`.
